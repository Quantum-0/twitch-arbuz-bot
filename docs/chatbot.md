# Чат-бот Twitch

> Справочник по фиче «чат-бот». При изменении поведения команд/конвейера —
> обнови этот файл в том же коммите.

Бот-аккаунт Quantum075Bot работает в чатах стримеров, подключивших бота
(флаг `enable_chat_bot`, панель `/panel/chatbot`). Сообщения приходят вебхуками
EventSub `channel.chat.message` (поток — `docs/architecture.md`, схема — `README.md`),
ответы уходят через Helix `send_chat_message` (`send_message_via_api`).

## Конвейер обработки сообщения (`twitch/chat/bot.py:on_message`)

метрики → бан-гейт (early-reject до БД, см. `docs/bans.md`) → **префильтр** → загрузка стримера
(User + settings/links/memealerts/tts) → учёт активных юзеров (`UserListManager` —
источник «рандомного чаттера» и поиска) → `CommandsManager.handle()` (команды) →
`MessagesHandlerManager.handle()` (хендлеры) → broadcast в SSE-канал `msg`
(для оверлеев с chat-control).

### Префильтр до БД (`_try_fast_path`)

На каждое сообщение стример раньше грузился из БД (SELECT + 4 JOIN + COMMIT),
хотя команды/хендлеры срабатывают на ~1-2% сообщений. Теперь после бан-гейта
сообщение проверяется без БД: первый токен (с учётом reply-префикса) входит в
множество алиасов всех команд (`CommandsManager.is_candidate`) ИЛИ хотя бы один
хендлер допускает срабатывание (`CommonMessagesHandler.is_candidate`,
агрегирует `MessagesHandlerManager.is_any_candidate`). Не совпало ни с чем →
быстрый путь: метрика `MESSAGE_INCOMING` с subtype `prefiltered`, список активных
и SSE-broadcast работают и без стримера, БД не трогаем вовсе.

Контракт `is_candidate`: результат — надмножество реальных условий `handle`
(False только при гарантированном SKIPED), внутри нельзя ходить в БД (Redis/текст —
можно); дефолт `True` — новый хендлер без предиката не отключает оптимизацию.
Анкорные триггеры (regex `match` от начала строки, «+»/«-» раффла) обязаны
проверять текст И после снятия reply-префикса — `CommandsManager.handle` срезает
«@имя » до хендлеров, и `handle` видит уже постриптованный текст (хелпер
`text_without_reply_prefix`). Настройки стримера (`enable_*`) в префильтре
неизвестны — сообщение с алиасом выключенной команды «промахивается» и грузит
стримера зря, это сознательный компромисс.

`MESSAGE_INCOMING` инкрементится ровно один раз на сообщение, subtype зависит
от маршрута: `""` — полный путь и бан-гейт, `prefiltered` — быстрый путь; сумма
подтипов = все входящие (фильтр по подтипу — на /stats).

## Подписки на чаты (`ChatBot.update_bot_channels`)

Подписки EventSub `channel.chat.message` для всех юзеров с `enable_chat_bot`:
подписывает новых, отписывает отключившихся. Ответ Twitch «subscription missing
proper authorization» → бот сам выключает `enable_chat_bot` в БД. Есть защита
от массовой отписки (`exception_to_many_unsubscribes`).

## Система команд

- Регистрация — список в `bot.py:startup()`, менеджер `twitch/chat/command_manager.py`.
- Матчинг: текст начинается с `!алиас ` или равен `!алиас` (алиасы ru/en); реплаи
  вида `@имя !команда` очищаются от префикса.
- Видимость: `is_enabled(settings)` — флаг `enable_*` из `TwitchUserSettings`
  (стример включает команды в панели, по категориям).
- Shared chats: при `allow_shared_chat=False` сообщения из общих чатов скипаются.

### Базовые классы (`twitch/chat/base/`)

- `Command` — база: имя, алиасы, доступ к StateManager/БД/отправке.
- `SimpleCDCommand` — кулдауны per-chat и per-user.
- `SimpleTargetCommand` — интерактив с целью: извлечение целей из текста
  (`twitch/utils.py:extract_targets` — `@ники` и алиасы «стримера/себя/кого-нибудь/
  рандом/всех»); при отсутствии цели — поведение из настройки канала
  `chatbot_default_target_behaviour` (TIP/STREAMER/RANDOM); отдельные ответы на
  «сам себя», «нашего бота», «другого бота» (`KNOWN_BOTS`, `utils/chat_roles.py`);
  per-user КД с «пакетом» (`cooldown_count` — несколько срабатываний за один КД).
- `SavingResultCommand` — «запоминаемый» результат: генерация значения, сохранение
  в стейте, отдельные ответы на новый результат и повторный запрос в течение
  `refresh_result_timer` («он всё ещё…» + дельта).

### Категории панели `/panel/chatbot`

1. «Взаимодействие между чаттерсами» — target-команды;
2. «Ссылки на соцсети»;
3. «Рандомайзеры» — «измерители» с запоминаемым результатом;
4. «Другое» (паста, лурк, трусы).

## Хендлеры-триггеры (`twitch/chat/handlers/`)

- `HelloHandler` — приветствия в адрес `@quantum075bot` или «всем» (25% шанс);
  у отдельных стримеров персонализированные варианты.
- `IAmBotHandler` — `@quantum075bot бот?` → подтверждение (10% — драматичная
  сценка из двух сообщений); «боты плюс» → бот ставит `+`.
- `ThanksHandler` — благодарность боту → «да не за что <3».
- `GiveMemesHandler` — «дай мемов/мемаф…», адресованное боту (реплай/тег) →
  отказ («неть», «не дам», «не хЪ»); при подключённой награде покупки мемкоинов
  (`memealerts_reward`) в пул добавляются наводящие варианты («только через
  награду 👀» и т.п.).
- `UnlurkHandler` — юзер в лурке >5 минут написал что-то → авто-«с возвращением».
  Лурк-стейт ключуется по display name — так же, как его пишет `!лурк`
  (`SimpleCDCommand` передаёт команде только display name; активность в
  `UserListManager` — тоже display name).
- `PyramidHandler` — трекинг эмодзи-пирамидок; **сейчас отключён** (`is_enabled → False`).

## Авто-шаутаут на рейды (`enable_shoutout_on_raid`)

EventSub `channel.raid` → shoutout рейдера от имени бота (`services/eventsub_service.py`).
Уважает лимиты Twitch (2 шаутаута в минуту / 1 на цель в час) через Redis-кулдауны
`shoutout:cd:*` / `shoutout:target:*`, очередь отложенных шаутаутов (cap 3),
ретраи при 429 (вкл. ручной шаутаут стримера), авто-отключение фичи, если бот
не модератор канала.

## Стейт

Кулдауны, счётчики, лурк, раффлы, «запоминаемые» результаты — Redis через
`StateManager` (`twitch/state_manager.py` + `services/redis_state_manager.py`):
ключи `sm:{channel}:{command}:{user}:{param}` + индексные множества, TTL 24 ч
(подробности — `docs/architecture.md`).

Конвенция ключа `{user}`: twitch-id (int) — везде, где id известен (кулдауны
команд, TTS, «запоминаемые» результаты, КД целей `!трусы` — резолв id активного
чаттера через `UserListManager.get_active_entries`, фолбэк — имя); display name
(str, в lower) — где writer имеет только имя (лурк, «упавший кубик», обнимашки;
`SimpleCDCommand`/`SimpleTargetCommand` передают в `_handle` display name).

## /cmdlist

Веб-страница `/cmdlist?streamer=X` (`routers/web/pages.py`) — только включённые
у стримера команды + временные команды оверлеев из Redis (`get_temp_commands`,
см. `docs/overlays.md`).

## Известные особенности

- `HornyBadCommand.command_name = "horny_good"` (`horny_bad.py`, копипаст) —
  good/bad-варианты `!хорни` неразличимы в стейте и метриках; на поведение
  не влияет (флаги включения разные), но при работе со стейтом учитывать.
