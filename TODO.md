## Авто-shoutout: очередь при серии рейдов (raid train) — DONE

Реализовано (см. `TwitchEventSubService._shoutout_with_cooldown` + `Twitch.shoutout` raw-httpx):
- лимиты Twitch: shoutout раз в 2 мин, той же цели — раз в 60 мин;
- twitchAPI.send_a_shoutout на 429 молча спит и теряет отправку — отправка идёт напрямую
  (httpx), статусы/Ratelimit-Reset парсим сами (`ShoutoutResult`);
- наши отправки: Redis `shoutout:cd:*` (120с) + `shoutout:target:*` (3600с, дедуп цели);
- под локом перепроверяем cd — одновременные ожидатели raid train не тратят API-вызовы;
- ручной shoutout стримера ловим реактивно (429 + Ratelimit-Reset): до 2 повторов,
  окно ожидания 150с на каждый сон, очередь ≤ 3 на канал — иначе drop с warning;
- 429 «the same broadcaster» → SAME_TARGET: пишем target-ключ (60-мин лимит цели);
- 400/403 (not moderator → авто-отключение флага + отписка; not live → warning);
- 401 → refresh_used_token под wait_for+shield (15с; у либы нет таймаута и refresh-лок
  отравляется при ошибке) + один ретрай.

## TTS — отложенные задачи

- Корреляция chat↔webhook: если зритель написал `!!!текст` в чате, а потом через секунду пришёл redemption за ту же награду — не озвучивать дважды (сейчас награда и чат-триггер независимы).
- Автомодерация toggle в `on_message` (не только для TTS): применять `ModerationService.validate()` ко всем сообщениям, не только к TTS-кандидатам. Сейчас модерация — первый шаг только внутри `TTSHandler`.
- Автобан: после N блокировок модерации за сессию — автоматический timeout/ban нарушителя (через `send_warning` + `delete_message`, которые уже реализованы).
- Роль «follower» (зритель-фолловер): в payload `channel.chat.message` нет признака follow-статуса. Для добавления роли нужен отдельный вызов Twitch API (get_followers) с кэшированием, либо проверка через EventSub subscription. Сейчас отложено — матрица 6 ролей без follower.
- ИИ-модерация: кроме статичного списка banned-слов, подключить LLM-классификатор для токсичности/спама/обхода фильтра (замена букв, обсфукация). Сейчас только regex+транслит.
- Списание баланса за TTS-генерации: `TTSService.synthesize` уже замеряет время, но не списывает баланс. Нужен счётчик генераций на пользователя и лимит/донат.
- TTS-награда: добавить `channel_points_custom_reward_id` из payload в `TTSHandler.handle` для надёжного skip'а (сейчас проверяется только наличие поля, без сравнения с `tts.tts_reward_id`).
